# 2026-10-02 工作日志

## 网站2（website2）— content(1).html 文章正文样式调整

- 模板性质：`content(1).html` 是 CMS（webber.wbst.com 系列）后台模板。正文/标题/图片由服务器端标签 `<!--#begineditable name="文章内容"-->elementname<!--#endeditable-->` 动态注入；直接静态打开只显示占位符 `elementname`，无真实图片。
- 用户需求1：锁死 `.article-body` 字号+字体。
  - 实现：`.article-body { font-size:17px !important; font-family: 微软雅黑栈 !important; }`；`.article-body * { font-family:inherit !important; font-size:inherit !important; }`（含 h2/h3 也统一成正文字号，用户明确"不用管标题/全部统一"）。
- 用户需求2：去掉空行，但保留行内空格（"不要空行，空格还是要"）。
  - 初版 JS（删空白 p/div/span + 折叠 `<br>`）太猛，会误删段落内空格，已废弃。
  - 最终版 JS（重新加回，更克制）：只遍历 `.article-body` 的**直接子** `<p>/<div>`，且只要内部含 `img/a/figure/table/ul/ol/iframe/video` 就整块保留；仅当元素 textContent 去掉 `&nbsp;` 和空白后为空（即空白行/仅含 `<br>` 的空行）才 `el.remove()`。绝不碰行内空格、绝不删图片。
  - 配套保留安全 CSS：`.article-body p:empty, div:empty, span:empty { display:none !important; }`（隐藏真正空元素）。
  - 关键约束：**不要折叠/删除单个 `<br>`**（用户要保留换行/空格）。
- 结论：字体锁定是纯 CSS，不会把图片变文字；图片乱码根因在 CMS 输出侧，待用户提供 CMS 图片实际标签（源码视图或浏览器 Inspect）再排查。
- 注意：`.article-body h2/h3` 里仍残留被覆盖失效的 font-size（21px/18px），仅装饰样式生效，可后续清理。
